    Class X509Cert

    Analyzes an X.509 certificate: the counterpart of the class X509Cert of the PHP library.

    It extracts the information of the certificate (subject, issuer, validity dates, fingerprint) and makes the checks the analysis of a token needs: the validity at the current date, the key usage, and the chain of the certificate up to trusted CA certificates (isTrustedBy()), which follows the rules OpenSSL applies for the PHP library. The certificate is parsed by OpenSSL (node:crypto), which also verifies the signature of each link of a chain; the fields node:crypto does not expose are read from the DER encoding of the certificate.

    isTrustedBy

    • isTrustedBy(
          caCerts: PemSource | PemSource[],
          options?: { at?: Date; untrusted?: readonly X509Cert[] },
      ): boolean

      Checks that the certificate is trusted: its chain is built and verified up to a self-signed certificate of the given CA certificates, with the rules OpenSSL applies for the PHP library (openssl_x509_checkpurpose(), purpose "any").

      Every given certificate is trusted, and the chain is built from these certificates only (and the untrusted ones), never from those of the system. A certificate is taken as the issuer of another one when its subject is the issuer of the other one (names compared in the canonical form of OpenSSL), when the authority key identifier of the other one matches it, and when its key suits the signature algorithm of the other one. Then:

      • OpenSSL verifies the signature of each link (but the root's own);
      • every certificate of the chain, the root included, is valid at the current date (or at at);
      • every issuer is a CA: basic constraints with "CA:TRUE" and, if it has a key usage, "keyCertSign"; the root may also be a CA by its key usage alone, or by being self-signed and of version 1;
      • the path length of each CA is respected;
      • no certificate has a critical extension the verification does not handle, nor a repeated or malformed extension.

      A chain that stops at an intermediate CA is rejected: to trust the certificates issued by an intermediate CA, give its certificate and the certificates up to its root. A certificate issued by another intermediate CA of the same root is then rejected, since the chain cannot be built without that other intermediate certificate.

      Name constraints are not enforced: a CA certificate that has them is rejected, where OpenSSL would enforce them.

      Parameters

      • caCerts: PemSource | PemSource[]

        The CA certificates: paths of PEM files, or PEM contents, each of which may hold several certificates.

      • options: { at?: Date; untrusted?: readonly X509Cert[] } = {}

        untrusted: certificates the chain may be built with, after the CA certificates, without being trusted (the intermediate CAs a signature embeds): the root must still be one of the CA certificates. at: the date the certificates must be valid at, instead of the current date.

      Returns boolean

      True if the chain of the certificate has been verified.

      Throws

      If a CA certificate file cannot be read.

    isValidCA

    • isValidCA(caCert: string | Uint8Array<ArrayBufferLike>): boolean

      Checks the origin of the certificate: it was issued by the given CA certificate. The CA certificate must be a CA ("CA:TRUE" basic constraint and, if it has a key usage, "keyCertSign"), the issuer of the certificate must have the fields of the subject of the CA certificate, and OpenSSL must verify the signature of the certificate with the key of the CA certificate.

      Only this link is checked: neither the validity dates nor the chain of the CA certificate. Use isTrustedBy() to verify the whole chain.

      Parameters

      • caCert: string | Uint8Array<ArrayBufferLike>

        The CA certificate, in PEM format (its content).

      Returns boolean

      Throws

      If the CA certificate cannot be read.
